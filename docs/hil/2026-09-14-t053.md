## Fails on real hardware, passes on the mock

1. **Off-centre FM station not resolved as a channel.** With the pipeline tuned 0.70–0.80 MHz from a 22 dB station (still inside the 1.8 MHz filter), `/api/inventory` showed one 0.9–1.2 MHz wide row near the window edge instead of a ~200 kHz station. The run summary counted 6 emitters while the default `/api/inventory` list returned 1 row; this mismatch is unexplained. On the mock, SIGNAL-062 passes with the station 500 kHz from centre. The live serve HIL at 100.8 MHz (500 kHz offset) did list 101.3 MHz. Suspect the detection/clustering path at the baseband-filter skirt on live 8-bit IQ, or the test's window choice. Needs a follow-up run with the station nearer centre (the serve HIL shape) before blaming the pipeline.
2. **No RDS PI on live air.** 0 decodes in both acceptance runs and in the serve HIL, although WFM chains attached. On the mock fixture (recorded with this same HackRF and these gains) the PI decodes. Either this station's RDS is weak here, or live chains skip to the live edge and lose RDS groups.
3. **Survey sensitivity.** At 8 Msps the strongest station stood only ~22 dB above the channel floor, and only one station reached 20 dB, so a within-band retune window could not be chosen. Survey at 2.4 Msps (or with more averaging) next time.

## T-084 offline follow-up (no hardware)

Reproduced from the committed HackRF captures (same gains) and synthetic scenes; the live re-run below confirms.

1. **Wide edge row.** Repro: the 20 Msps urban FM fixture (`urban_98M_20M_l32g30a1`) cut to a 2.4 Msps window at 102.0 MHz (101.31 MHz station, 21 dB, 0.7 MHz off centre) and replayed. The inventory held one row at 101.666 MHz, 1116 kHz wide, which matches run 1 (101.638 MHz, 1155 kHz). **Root cause:** it is not the floor or CFAR at the filter roll-off (the fixture floor is flat to ±1.1 MHz at these gains). It is a false **bursty hop set** (T-031). The weak stations' near-threshold flicker (narrow 5–56 kHz boxes at 4–7 dB mean SNR, at random times) chance-linked 19 "channels" across 101.10–102.24 MHz, and the hop set's channel span became the row. **Fix:** a hop-set member channel must have a mean detection SNR of at least `HopConfig::min_channel_snr_db` (8 dB). Replayed after the fix, there is no hop set; the station row is 101.305 MHz, 272 kHz, RDS PI decoded, confirmed. The weak stations' flicker now lists as narrow candidates instead. **Test:** `hk-detect` `near_threshold_bursty_flicker_does_not_form_a_hop_set`; the 15 dB hopper tests and the 915 MHz FHSS fixture still form hop sets.
2. **6 emitters vs 1 row.** It is neither `same_emission` nor the state filter: the hop-presence gate keeps hop sets apart, and the summary and API use the same default states. It is a **counting-time difference**: the inventory records a track only when it closes, and a continuously tracked station's track closes at stop. Repro: a real-time mock run of the FM fixture listed 1 row (the RDS chain entry) at 15 s and 30 s, while the summary counted 31 after stop. **Fix:** the summary line and `RunSummary.emitters` now say they count after stop; the HIL test logs both counts. Listing open confirmed tracks mid-run is a follow-up.
3. **No RDS live.** RDS PI decodes offline at HackRF levels 0.7 MHz off centre (urban cut: PI 1694), and in real-time mock runs (the chain windows shrink to the 0.5 s probe but still decode). The limit found: in a dense band where neighbours 200 kHz away are as strong as the station, the probe's OBW99 abstains (`FillsBand`), mode selection returns unknown and the chain is mode-rejected (synthetic 14-station scene, 60 kHz deviation). Live, the false hop set also hid the station row. For the re-run, check `mode rejected` against attached chains and `HK_PIPELINE_DEBUG=1` probe lines (now printing OBW99 and the reason) for the station.

The HIL test now surveys at 2.4 Msps (0.6 MHz steps, survey-wide 10th-percentile floor), runs with the strongest station 0.5 MHz from centre (the `hackrf_serve_hil` shape), fails on any inventory row wider than 500 kHz and logs the inventory count at stop beside the summary's.
