# T-565 — the search trace, produced inside the beam: what landed and what was measured

T-854 (M-3) had already built most of ADR-0021 §2–§3: the twelve-variant `Outcome` with the served
`tried` flag, a `TraceSink` called at every frontier-removal site, retention on insert, `elided`
buckets and the `progress` split. T-565 closed the gaps against its acceptance and measured the cost.

## What changed

- **`replay_key` (ADR-0021 §5)** — `hk_synth::trace::ReplayKey {engine, templates, blocks
  [{name, version}], calibration_hash, window, profile, budget {count caps + cache cap}, seed_ref}`.
  `seed_ref` is the SHA-256 of the canonical seeding: roots, unsupported suspicions, solve rule and
  trace bounds. The engine returns it on `SearchOutcome`, and hk-pipeline records it on
  `AnalyzeJob.replay_key` (with `window` filled from the read ledger), on `resolution.replay_key`
  and on the trace fetch, which served `null` before. `docs/api.md` is updated.
- **`TraceNode.nondeterministic`** — set on a `deferred_budget` node left by a time-caused stop
  (the wall/CPU backstop, a plateau measured against wall, a cancel) and on `refused_power`. A
  `deferred_budget` node behind a **count** cap is deterministic and is not flagged: this follows
  ADR-0021 §5's own condition ("any decision whose cause is a wall-clock or CPU-time cap") and
  keeps count-bounded acceptance jobs replayable. Any flagged node implies
  `SearchOutcome.nondeterministic`, which clears `trace_summary.replayable`. A cancel now also marks
  the job non-replayable.
- **Not-tried rows are now few, as ADR-0021 §2.3 assumes.** Before, a stop that left N discrete
  plans (e.g. 260 CRC polynomials) wrote N `deferred_budget` nodes. Those are never droppable, so
  under a 40-node cap the trace sat at **295 nodes (`over_bound`)**. The rows are now one node per
  (parent, slot alternative), whose summary gives the count; the same applies to same-level
  duplicates. Afterwards the peak was 40 with nothing over bound.
- **Retention is incremental.** The sink used to rescan and re-sort the whole retained set on every
  insert. It now keeps ordered indexes (best per (stage, family), top-2 floors, top-10 rank,
  droppable leaves), so each insert is O(log n). A unit test checks every victim choice against the
  original rescan, over randomised trees under both bounds. Byte counting streams through a
  counting writer instead of allocating a buffer per node.
- **`Trace.peak_nodes` / `peak_bytes`**: residency is sampled after every insert, so the bound is
  checked during the search and not only at its end. `SearchSpec.trace_bounds` defaults to the
  profile's bounds and can be narrowed, which is how the tests make the bound bite.
- `TraceCost` gains `retention_s` and `decisions`, and the sink exposes `in_trace_scope()`, a
  thread-local flag that a counting allocator can read.

## Measured cost (`search_engine::the_trace_cost_is_measured_not_assumed`)

This is a crowded synthetic space: 3 skeletons × 251 CRC polynomials, never solving, one thread. A
counting global allocator splits allocations into trace work and the rest. The synthetic evaluator
is nearly free, so "% of search" is an upper bound. The projected column uses docs/27 §3's
≤ 5 ms per cached-stage evaluation.

| build | shape | decisions | trace wall | per decision | % of free-evaluator search | projected @ 5 ms/eval | trace allocations |
|---|---|---|---|---|---|---|---|
| debug, rescan (before) | quick, 128-node cap | 517 (389 elided) | 161.7 ms (retention 155.5) | 313 µs | 63.6 % | 10.2 % | 17.7 % |
| debug, incremental | quick, 128-node cap | 517 (389 elided) | 27.1 ms (retention 22.5) | 52 µs | 21.4 % | 1.9 % | 6.5 % |
| **release, incremental** | quick, 128-node cap | 517 (389 elided) | 4.0 ms (retention 1.8) | **7.8 µs** | 17.3 % | **0.28 %** | 6.5 % |
| **release, incremental** | deep, 2048 / 256 KiB | 517 (0 elided) | 1.8 ms (retention 0.7) | **3.5 µs** | 11.3 % | **0.13 %** | 8.2 % |

**Verdict: ADR-0021's "negligible" claim holds, but only after the retention fix.** With the
original rescan a bound-limited job paid ~10 % of a realistic search to its trace in a debug build.
The O(n log n)-per-insert rescan would also have grown with deep's 2 048-node set. The allocation
share is measured against a free evaluator. A real evaluator allocates IQ-sized buffers, so the
real share will be far smaller. The M-13 Jetson baseline should re-measure both.

**Bytes per node are higher than ADR-0021 §2.3 assumed.** The measured size is ~480 B per node with
its rendered summary, against the ADR's 200–400 B. At deep, 517 nodes already hold 250 KB of the
256 KiB byte cap, so the byte cap binds at ~540 nodes, well before the 2 048-node cap. That fits the
ADR's intent (the byte cap is the hard limit), but the node cap is a quarter as reachable as the
ADR's arithmetic suggests.
